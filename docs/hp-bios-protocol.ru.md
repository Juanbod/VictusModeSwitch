# Связь OMEN Gaming Hub с BIOS

[English version](hp-bios-protocol.md)

> [!CAUTION]
> Это независимое описание, полученное исследованием, а не спецификация HP.
> Интерфейс недокументирован, требует повышенных прав и зависит от конкретной
> платы и версии BIOS. Неизвестные команды записи нельзя проверять на ноутбуке,
> потерю которого вы не готовы принять.

Состояние исследования: **08.09.2026**. Victus Mode Switch выполнял запись в
BIOS только на HP Victus 15-fa0xxx с системной платой `8A4F` и HP Thermal Policy
`V0`.

## Уровни подтверждения

| Метка | Значение |
|---|---|
| **Проверено на 8A4F** | Значение прочитано на тестовом ноутбуке либо команда реально использована Victus Mode Switch и BIOS вернул успех. |
| **Обнаружено в OGH** | Интерфейс восстановлен из установленных компонентов актуального OMEN Gaming Hub и HP HSA. |
| **Подтверждено upstream** | Такое же поведение реализовано в драйвере Linux `hp-wmi` или независимом открытом проекте. |
| **Кандидат** | Команда выглядит полезной, но намеренно не вызывалась на тестовом ноутбуке. |

В репозиторий не добавлены бинарники HP, декомпилированный код, ключи или файлы
пакета OMEN. Здесь зафиксированы только форма интерфейса и наблюдаемое поведение.

## Путь команды

В актуальной версии OMEN используется такая цепочка:

```text
OMEN Gaming Hub MSIX
  -> клиент WMISDK
  -> локальный RPC HPSysInfoRpcEndpoint / служба WMIService
  -> HP Omen HSA Service (HPOmenCap)
  -> провайдер HP WMI/ACPI
  -> embedded controller и прошивка
```

На тестовом ноутбуке обнаружены:

| Компонент | Версия |
|---|---|
| Системный BIOS | `F.29` |
| OMEN Gaming Hub | `1101.2605.2.0` |
| HP Omen HSA Service (`HPOmenCap`) | `OmenCap.exe` `1.0.838.0` |
| Управляемый клиент HP WMISDK | `1.3.10` |
| Компонент возможностей устройства HP | `3.0.1.4580` |

Клиент Gaming Hub сериализует команду и отправляет локальную RPC-команду `2`
на endpoint `HPSysInfoRpcEndpoint`, указывая службу `WMIService`. Ответ содержит
`returnCode` и `returnData`. Например, чтение System Design Data выглядит так:

```json
{
  "command": 131080,
  "commandType": 40,
  "inputDataSize": 4,
  "inputData": [0, 0, 0, 0],
  "returnDataSize": 128
}
```

Здесь `131080 = 0x20008`, а `40 = 0x28`. Это приватный локальный интерфейс HP,
а не сетевой API. Текущая служба HSA проверяет доверие к вызывающему пакету.
Victus Mode Switch не маскируется под Gaming Hub и не обходит эту проверку.

Наше приложение использует более узкий прямой путь и разрешает только заранее
зафиксированные операции:

```text
обычный процесс в трее
  -> named pipe только для текущего пользователя
  -> короткая повышенная задача BIOS-брокера
  -> root\wmi / hpqBIntM
  -> прошивка
```

## Транспорт HP WMI

На плате `8A4F` обнаружена следующая схема:

| Элемент | Значение |
|---|---|
| Namespace | `root\wmi` |
| GUID BIOS WMI | `5FB7F034-2C63-45E9-BE91-3D44E2C707E4` |
| GUID событий WMI | `95F24279-4D7B-4334-9387-ACCDC67EF61C` |
| Класс методов | `hpqBIntM` |
| Входной класс | `hpqBDataIn` |
| Выходные классы | `hpqBDataOut0`, `hpqBDataOut4`, `hpqBDataOut128`, `hpqBDataOut1024`, `hpqBDataOut4096` |
| Класс событий | `hpqBEvnt` |
| Методы | `hpqBIOSInt0`, `hpqBIOSInt4`, `hpqBIOSInt128`, `hpqBIOSInt1024`, `hpqBIOSInt4096` |

Логическая структура `hpqBDataIn`:

| Поле | Тип | Назначение |
|---|---|---|
| `Sign` | массив байтов | `53 45 43 55`, ASCII `SECU` |
| `Command` | `UInt32` | Семейство команд, обычно `0x20008` для игровых настроек |
| `CommandType` | `UInt32` | Операция внутри семейства |
| `Size` | `UInt32` | Число значимых байтов во входном буфере |
| `hpqBData` | массив байтов | Входные данные |

Имя WMI-метода задает размер выходного буфера. В `OutData` возвращаются
`rwReturnCode` и массив `Data`:

| Нужный размер | Метод |
|---:|---|
| 0 байт | `hpqBIOSInt0` |
| 1-4 байта | `hpqBIOSInt4` |
| 5-128 байт | `hpqBIOSInt128` |
| 129-1024 байта | `hpqBIOSInt1024` |
| До 4096 байт | `hpqBIOSInt4096` |

Коды ответа, также подтвержденные драйвером Linux:

| Код | Значение |
|---:|---|
| `0` | Успех |
| `2` | Неверная сигнатура |
| `3` | Неизвестная команда |
| `4` | Неизвестный тип команды |
| `5` | Неверные параметры |

Одни клиенты HP передают при чтении четыре нулевых байта, другие используют
`Size=0`. На `8A4F` встречаются оба рабочих варианта. Размер является частью
контракта конкретной команды и конкретной платы.

### Альтернативный кадр драйвера HP

В текущем Gaming Hub также есть путь через отдельный драйвер. Он формирует
входной и выходной буфер размером 4116 байт:

| Смещение | Длина | Значение |
|---:|---:|---|
| `0x0000` | 4 | `SECU` |
| `0x0004` | 4 | `Command`, little-endian |
| `0x0008` | 4 | `CommandType`, little-endian |
| `0x000C` | 4 | Входной размер 0, 4, 128, 1024 или 4096 |
| `0x0010` | 4096 | Область данных |
| `0x1010` | 1 | Выходной селектор: 1=0, 2=4, 3=128, 4=1024, 5=4096 |

После вызова клиент читает сигнатуру результата из байтов `0..3`, код BIOS из
байта `4`, а данные начиная с байта `8`. Victus Mode Switch этот путь не
использует; структура записана только для полноты картины.

## Событие кнопки OMEN

Кнопка с ромбом приходит через класс `hpqBEvnt`:

| Поле | Значение на этом ноутбуке |
|---|---:|
| `EventID` | `29` (`0x1D`, `HPWMI_OMEN_KEY`) |
| `EventData` | `8613` |

Плата `8A4F` отправляет один импульс на нажатие. Отдельного события отпускания
или повторов при удержании нет, поэтому надежно распознать удержание нельзя.

## System Design Data платы 8A4F

Gaming Hub читает `0x20008 / 0x28`, получает 128 байт и сохраняет кэш в:

```text
HKCU\Software\HP\OMEN Ally\Settings\SystemDesignData
```

Текущий блок начинается с `C8 00 00 00 00 00 00 00 00`; остальные байты равны
нулю. OMEN Gaming Hub `1101.2605.2.0` интерпретирует важные поля так:

| Смещение | Смысл | Значение 8A4F | Вывод |
|---:|---|---:|---|
| `0..1` | Мощность штатного блока питания, Вт, little-endian | `200` | Достигнут порог Gaming Hub для Performance. |
| `3` | Версия Thermal Policy | `0` | Нужно использовать значения V0. |
| `4`, бит 0 | Программное ручное управление вентиляторами | `0` | Ручные кривые не включаем. |
| `4`, бит 1 | Поддержка Extreme | `0` | Extreme не включаем. |
| `4`, бит 2 | Разблокировка Extreme | `0` | Пути разблокировки нет. |
| `6` | Флаг разгона через BIOS | `0` | Разгон BIOS не включаем. |
| `7` | Флаг переключателя графики | `0` | GPU MUX не показываем. |
| `8` | Поле стандартного concurrent TDP | `0` | Пригодное значение платформа не сообщила. |

Во внутреннем каталоге актуального OMEN плата `8A4F` называется `Roku`, цикл
`22C1`, GPU SKU `N20P`; для нее явно разрешен Performance Control. Для семейства
Roku также указан модуль `FourZone`, но поддержку подсветки конкретной клавиатуры
Gaming Hub проверяет отдельно во время работы.

Значения профилей Thermal Policy V0:

| Профиль | Значение |
|---|---:|
| Default | `0x00` |
| Performance | `0x01` |
| Cool | `0x02` |

Для V1 обнаружены Default `0x30`, Performance `0x31`, Cool `0x50`. Наше
приложение блокирует V1, а не переносит на него непроверенные значения.

Отдельного аппаратного Eco у этой V0-платы нет. Gaming Hub переводит Eco в
Default, и Victus Mode Switch делает то же самое. Дополнительная экономия в
нашем Eco обеспечивается настройками питания Windows и выключением Max Fan.

## Карта игровых команд

Если не указано иное, используется внешняя команда `0x20008` (`HPWMI_GM`).
Название «чтение» не гарантирует полного отсутствия побочных эффектов прошивки.

| Тип | Операция | Формат | Статус в проекте |
|---:|---|---|---|
| `0x10` | Число вентиляторов | Четыре входных байта, число в байте 0 ответа | OGH и upstream. В Linux этот запрос также поддерживает пользовательский режим вентиляторов с откатом через 120 секунд, поэтому пока только кандидат. |
| `0x11` | Обороты вентилятора | Входной байт 0 задает индекс; RPM находится в байтах 2..3 ответа, big-endian | Upstream. Кандидат для телеметрии. |
| `0x1A` | Установка теплового профиля | `[FF, profile, fanControlByBios, 00]` | **Проверено на 8A4F.** Разрешены только V0-профили 0 и 1. |
| `0x21` | Чтение состояния питания GPU | Четыре байта: cTGP, PPAB, D-state, температура замедления | OGH и upstream. Кандидат для телеметрии. |
| `0x22` | Запись состояния питания GPU | Те же четыре логических поля | Отключено: значения зависят от GPU и BIOS. |
| `0x23` | Температура датчика платформы | Входной байт 0 выбирает датчик, температура в байте 0 ответа | OGH. В коде встречаются IR, ambient, PCH и VR, но соответствие индексов пока предварительное. |
| `0x26` | Чтение Max Fan | Состояние в байте 0 | **Проверено на 8A4F.** |
| `0x27` | Запись Max Fan | Первый байт 0 или 1 | **Проверено на 8A4F.** |
| `0x28` | Чтение System Design Data | Четыре нулевых байта у OGH, ответ 128 байт | **Проверено на 8A4F.** Используется как предохранитель записи. |
| `0x29` | Запись лимитов мощности | Четыре платформозависимых байта | Отключено: порядок PL1/PL2 и допустимые диапазоны различаются между поколениями. |
| `0x2A` | Чтение данных мощности | 128 байт; текущий OGH читает PL4 из байта 6 и concurrent TDP из байта 7 | Кандидат, раскладка на 8A4F не проверена. |
| `0x2B` | Тип клавиатуры | Ответ 4 байта | Кандидат для проверки возможностей. |
| `0x2C` | Типы и возможности вентиляторов | 128 байт; типы в nibble байтов 0..3, флаги в байтах 8..9 | Кандидат для проверки возможностей. |
| `0x2D` | Уровни вентиляторов Victus | 128 байт; Linux для Victus-S трактует байт вентилятора как сотни RPM | Кандидат для телеметрии. |
| `0x2E` | Запись уровней вентиляторов | Два или более байта уровней | Отключено: нужны пределы конкретной модели и периодический keepalive. |
| `0x2F` | Чтение таблицы вентиляторов | Ответ 128 байт | Кандидат для исследования. |
| `0x31` | Настройка idle-поведения | Текущий OGH использует первый байт как bool | Смысл изучен не полностью, отключено. |
| `0x35` | Диагностические подкоманды | Формат зависит от подкоманды | Предварительно, отключено. |
| `0x36` / `0x37` | Чтение/запись расширенной конфигурации мощности | Новые двухбайтовые поля мощности и load-line | Эта система поддержку не заявляет; запись отключена. |

Также обнаружены семейство `0x20009` для подсветки клавиатуры, `0x2000B` для
чтения сценария USB-C и общий запрос HP `Command=1`, `CommandType=0x52` для
состояния graphics switcher. Мы их пока не вызываем: наличие кода в Gaming Hub
не доказывает поддержку конкретным ноутбуком.

## Что разрешено приложению

BIOS-брокер не принимает произвольные номера команд или массивы байтов. Перед
записью он проверяет плату `8A4F`, читает System Design Data и требует Thermal
Policy V0. Вся разрешенная поверхность состоит из четырех сценариев:

| Действие | Последовательность BIOS |
|---|---|
| Eco | `0x1A [FF 00 00 00]`, затем `0x27 [00 00 00 00]`, проверка через `0x26` |
| Стандартный | `0x1A [FF 00 00 00]`, сохранение выбранного Max Fan, проверка через `0x26` |
| Performance | `0x1A [FF 01 00 00]`, сохранение выбранного Max Fan, проверка через `0x26` |
| Переключение Max Fan | Повтор текущего профиля, `0x27` с 0 или 1, проверка через `0x26` |

Обычный процесс создает pipe `VictusModeSwitch.Bios.<SID-with-dots>` только для
текущего пользователя и запускает задачу `Victus Mode Switch BIOS`. Один JSON с
переводом строки содержит `Id`, `Mode`, `MaxFanEnabled`, `CreatedAt`; ответ
содержит `Id`, `Success`, `Message`, подтвержденный `MaxFanEnabled`. Брокер
отклоняет старый запрос, неизвестный режим, неподдерживаемое железо и
неподтвержденное состояние Max Fan.

## Какие функции можно добавить

Самое полезное и аккуратное расширение выглядит так:

1. Отчет о возможностях платы и расшифровка System Design Data.
2. Обороты вентиляторов с редким опросом и отдельным профилем платы.
3. Температуры и текущее состояние питания GPU после сверки с независимым
   мониторингом датчиков.
4. Отдельная безопасная проверка поддержки подсветки клавиатуры, без записи до
   подтверждения типа клавиатуры и точного формата данных.

Ручные кривые вентиляторов, запись cTGP/PPAB, PL1/PL2/PL4, Extreme и GPU MUX на
`8A4F` сейчас добавлять нельзя. Нужные capability-флаги равны нулю, а последствия
неверного значения существенно серьезнее потенциальной пользы.

## Безопасная диагностика

В репозиторий добавлен скрипт инвентаризации:

```powershell
.\scripts\Inspect-HpBiosInterface.ps1 -OutputPath .\artifacts\hp-bios-interface.json
```

Он читает сведения Windows, описание WMI-классов, версии OMEN/HSA и уже
существующий реестровый кэш Gaming Hub. Скрипт намеренно не вызывает ни одного
метода `hpqBIOSInt*`, поэтому не читает прошивку и ничего в ней не меняет. В
отчет не включаются серийный номер и SID пользователя.
